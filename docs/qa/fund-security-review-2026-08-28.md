## 最终权限模型

### 项目总资金

- 查看、创建、修改：系统管理员。

### 拨付管理

- 汇总数据：所有已登录用户可看。
- 计划列表、详情、拨付记录及附件名称：管理员或当前课题成员可看。
- 创建、修改、删除计划：系统管理员。
- 指定责任人：系统管理员，或课题中配置的拨付单位负责人。
- 候选责任人：仅返回该课题、该拨付单位的有效成员。
- 提交拨付：已指定责任人时仅责任人；未指定时仅拨付单位负责人；管理员可处理。
- 修改、删除拨付记录：除满足计划操作权限外，还必须是记录提交人；管理员可处理。
- 结束计划：责任人、拨付单位负责人或管理员。

### 使用管理

- 汇总、计划、记录及附件：管理员或当前课题成员可看。
- 创建、修改、删除使用计划：课题负责人或管理员。
- 使用计划必须指定当前课题成员作为责任人。
- 提交、结束使用：当前责任人或管理员。
- 历史遗留的无责任人计划：课题负责人可处理。
- 修改、删除使用记录：除满足计划操作权限外，还必须是记录提交人；管理员可处理。
- 超计划强制结束：非负责人发起后由课题负责人确认；管理员可确认。

### 附件

- 上传接口只允许拥有拨付记录或使用记录权限的用户调用。
- 单文件上限 5MB，仅允许 `pdf/doc/docx/xls/xlsx/jpg/jpeg/png`。
- 上传后仅返回一次性 token，不向浏览器暴露物理文件 URL。
- token 绑定上传人、30 分钟有效、只能使用一次，并通过数据库行锁防止并发复用。
- 任意 URL、伪造 token、他人 token、过期 token 和已用 token 均拒绝绑定。
- 下载必须重新执行课题成员权限校验，不能依靠拿到 URL 绕过业务权限。

## 已修复问题

### FUND-FUNC-001：拨付/使用提交按钮使用过期权限码

- 原因：前端仍判断 `fund:allocation:submit` / `fund:use:submit`，后端和数据库已使用 `record`。
- 修复：统一为 `fund:allocation:record` / `fund:use:record`，并同步初始 SQL 和幂等迁移。
- 状态：已修复并通过责任人角色测试。

### FUND-AUTH-001：任意登录用户可枚举全部部门及部门用户

- 修复：部门接口需要计划维护权限，且只返回 `deptId/deptName`；删除任意部门用户接口，改为计划作用域候选人接口并校验单位负责人。
- 状态：已修复；outsider 被拒绝，旧接口返回 404。

### FUND-DATA-001：公共课题选项返回完整业务对象

- 修复：公共下拉只返回 `groupId/groupCode/groupName`。
- 状态：已修复。

### FUND-ATTACH-001：附件关系信任客户端文件 URL

- 修复：新增 `fund_upload_receipt`，由 Fund 调用文件服务上传并签发一次性凭证；记录接口拒绝非空 `voucherUrls`。
- 状态：已修复；上传人绑定、复用、伪造及跨课题下载均已测试。

### FUND-UI-001：按钮显示与后端业务能力不一致

- 修复：计划 DTO 返回 `canSubmitRecord/canAssignResponsible/canFinish/canConfirmForceFinish`，记录 DTO 返回 `canEdit`；前端以菜单权限和后端能力共同决定按钮。
- 状态：已修复。

### FUND-DEPLOY-001：初始 SQL 与升级 SQL 权限码不一致

- 修复：`sql/ry_fund.sql` 和 `sql/update/008_fund_security_hardening.sql` 统一为 `record` 权限。
- 状态：已修复，本地 MySQL 5.7 migration 已成功执行。
